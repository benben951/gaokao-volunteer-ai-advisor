# Data Governance

## 公开仓库的数据边界

本仓库只提交样例数据，不提交真实全量数据。

不能提交：

- `.env`、API Key、访问码、云账号凭证
- 从商业平台购买/下载的完整数据
- 未授权转载的招生计划、录取明细、PDF 原文
- 含个人信息的咨询记录
- 真实用户的分数、位次、手机号、微信号

可以提交：

- 手写的少量样例数据
- 数据库 schema
- 导入流程说明
- 脱敏后的字段样例
- 推荐算法代码
- 数据质量检查规则

## 数据源分级

### A 类：官方数据

优先级最高。

例子：

- 河南省教育考试院
- 阳光高考
- 院校招生章程
- 院校官网招生网

用途：

- 批次规则
- 招生计划
- 选科/体检/单科要求
- 正式投档线

### B 类：聚合平台数据

需要交叉校验。

例子：

- 中国教育在线
- 掌上高考
- 第三方志愿平台

用途：

- 分专业录取线参考
- 院校画像补充
- 专业介绍补充

### C 类：就业和城市数据

只能用于趋势解释，不能用于录取判断。

例子：

- 国家统计局
- 各地统计年鉴
- 智联、BOSS、猎聘年度报告

用途：

- 城市收入/成本估算
- 职业趋势解读
- 人生模拟参数

## 数据库字段建议

每条录取数据至少保留：

- 年份
- 省份
- 科类
- 批次
- 学校
- 专业
- 最低分
- 最低位次
- 招生计划数
- 数据来源
- 导入时间
- 来源 hash

## 数据质量检查

导入前检查：

- 分数是否在 0-750
- 位次是否为正整数
- 年份是否合理
- 学校名是否能与学校表匹配
- 专业名是否为空
- 同一学校/专业/年份/批次是否重复

推荐前检查：

- 用户输入分数是否合法
- 位次和分数是否大致匹配
- 科类是否与数据源一致
- 当年数据缺失时必须标记“参考往年”

AI 输出检查：

- 不允许出现候选池外的“确定推荐”
- 不允许生成虚假分数线
- 不允许承诺录取
- 必须提醒以官方数据为准

## 开源前敏感信息扫描

建议每次提交前运行：

```powershell
rg -n "sk-[A-Za-z0-9]{12,}|AKID[A-Za-z0-9]{12,}|SecretKey|vcp_|DEEPSEEK_API_KEY|ACCESS_CODE" . -g "!node_modules/**"
```

如果命中 `.env.example` 里的占位符，需要确认它不是实际密钥。

## 真实数据如何使用

生产环境建议：

1. 原始数据放在私有目录或对象存储。
2. 导入脚本清洗后写入数据库。
3. 后端 API 查询数据库并返回候选池。
4. 前端只接收结果，不接收全量数据。
5. LLM 只读取候选池和用户画像。
